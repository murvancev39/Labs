## Цель работы

Сравнить два варианта sparse table n строк по log n или наоборот. И сравнить Дерево отрезков и Дерево Фенвика.

---

## Структура проекта

* `/bin` — тут лежат экзешники, а точнее будет один, который при запуске с разными флагами и путями, будет проводить тесты для всех пунктов.
* `/src/RMQ | /src/RSQ` — реализации деревьев и таблицы.
* `/src/testing` — реализации тестирующей системы.
* `/res` — результаты тестирования для всех деревьев.
* `/include` — заголовочные файлы.


---

## Реализации и Итоги

### Деревья


#### 1. RMQ
* **Кто выиграл** N строк по log n. Примерно одинаковые результаты, разве что N log n чуть быстрее.  Как я  понял, что чуть быстрее из-за того что если отрывки, находятся рядом, то подмассивчики в памяти располагаются недалеко (так как длины массивов по логарифму а не ляму), доступ быстрее получается.


#### 1. RSQ
* **Кто выиграл** Фенвик оказался быстрее. Мне кажется это изза того что у ДО константа больше, оно делает просто больше лишних операций. Да и массив для ДО больше раза в 2, изза чего может быть больше кэш промахов и тд.

## Тестирование

Все тесты сделаны на массиве из 1000000 элементов, для фенвика и ДО при тестировании в случайном порядке вызывается либо поиск суммы на отрезке, либо апдейт значения элемента. Для RMQ только поиск на отрезке.
 
---


## Запуск

```bash
make all             # Скомпилировать проект изначально режим debug
make run_all         # Запустить тесты для всего
make run_rmq_n_logn  # Запустить тест только для Sparse table для N строк по логарифму

make run_all MODE=release  # Тесты, в  релизной версии, только перед прогоном удалить все бинарники и тд

make clean           # Удалить объектники, бинарник и результаты тестов в res/
```
